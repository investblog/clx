Confidentialité des outils QR code

Version du 12 novembre 2026.

Ceci est une traduction ; la version anglaise fait foi. Version anglaise.

Cette politique couvre les outils QR code gratuits de clx : le générateur de QR code de ce site, l’API de QR codes sur qr.clx.cx et l’extension de navigateur (sa page). Aucun d’eux ne demande de compte, ne dépose de cookie, n’affiche de publicité ni ne fait de mesure d’audience. La politique des comptes clx fait l’objet d’une autre page (en anglais).

Le générateur de ce site

Le QR code est dessiné dans votre navigateur. Ce que vous saisissez n’est envoyé nulle part : la page n’effectue aucune requête qui le contienne. Le lien de l’image et le HTML affichés sont eux aussi construits dans le navigateur ; ils n’atteignent l’API que lorsque quelqu’un les ouvre. Le générateur ne conserve rien de ce que vous saisissez et ne dépose aucun cookie ; ce que le site lui-même conserve — le thème, le code d’un partenaire issu d’un lien — est décrit sur la page de confidentialité de clx (en anglais).

L’API sur qr.clx.cx

L’API reçoit une requête quand un lien vers elle est ouvert — par vous, ou par le navigateur de quiconque consulte une page ou un e-mail qui affiche une telle image. La requête contient le texte à encoder, la taille, la correction d’erreurs et la marge, ainsi que, comme toute requête sur le web, l’adresse IP de la personne qui consulte, son navigateur (User-Agent) et souvent la page d’où elle vient (Referer). L’API :

  • n’utilise le texte que pour dessiner l’image et vérifier le hachage du lien ;
  • ne tient aucun journal des requêtes et ne stocke aucune image ; seules les réponses de /qr.inline restent 24 heures dans le cache de Cloudflare, indexées par leur adresse complète, puis expirent ;
  • ne compte, ne profile et ne suit personne.

Un QR code n’est pas un secret : quiconque possède son lien, ou le scanne, lit son texte. N’encodez pas de mots de passe ni d’autres secrets.

L’extension de navigateur

Depuis la version 1.1.0, l’extension n’effectue plus aucune requête réseau : les codes et les liens de partage sont créés dans le navigateur. Les versions antérieures à 1.1.0 envoyaient le texte de chaque code créé à l’API, à son ancienne adresse, qr.qrcgen.com. Les autorisations de l’extension :

  • panneau latéral — pour afficher sa fenêtre (Chrome, Edge ; Firefox affiche une barre latérale sans autorisation) ;
  • stockage — pour conserver vos réglages (thème, taille et correction d’erreurs par défaut, limite de l’historique, génération à l’ouverture) et l’historique des codes dont vous avez copié le lien, uniquement dans votre navigateur ;
  • onglets — pour lire l’adresse de la page actuelle et créer son code.

Rien de ce que l’extension conserve ne quitte votre navigateur ni n’est synchronisé ; la désinstaller le supprime.

Qui traite les données

L’API et les pages de ce site fonctionnent sur Cloudflare (Workers), à l’exception des pages en russe (ru.clx.cx), hébergées sur GitHub Pages ; chacun traite les requêtes qu’il sert en tant qu’hébergeur, selon sa propre politique. Nous n’ajoutons aucun outil de mesure d’audience, ni de Cloudflare ni de quiconque ; nous ne voyons que le nombre de requêtes et d’erreurs que Cloudflare affiche à tout compte, sans leur contenu. Aucune donnée n’est vendue ni partagée avec qui que ce soit.

Enfants

Les outils QR code ne collectent délibérément aucune information personnelle, de qui que ce soit, enfants compris, et ne conservent rien au-delà du cache de 24 heures de /qr.inline décrit plus haut ; ce qu’une requête contient d’elle-même y est également décrit.

Toute modification de cette politique change la date indiquée en haut de la page. Questions : via le formulaire de contact accessible en bas de chaque page, ou par un ticket (issue) dans le dépôt de l’API, github.com/investblog/qr-generator. Abus d’un QR code : comment le signaler (en anglais).
